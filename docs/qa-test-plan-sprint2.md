## 1. PLGオンボーディングフロー

### 前提・設計確認ポイント

- フロー発火条件: `user.created_at` から 72h 以内 **かつ** アプリ登録数 = 0
- 管理方法: `localStorage['onboarding_completed']` = `'true'` で完了扱い
- スキップ後: 24h 後に Header 下バナーを 1 回のみ表示
- Activation 定義: キーワード 3 件以上登録 + 初回順位データ受信

---

### TC-PLG-01: 初回ログイン時にフローが表示される（正常系）

**優先度**: 🔴  
**前提**: 新規作成ユーザー、localStorage に `onboarding_completed` なし、アプリ登録数 = 0  
**手順**:
1. 新規ユーザーでログイン
2. トップページが表示される

**期待値**:
- STEP 1/3 ウェルカムオーバーレイが全画面で表示される
- 背景コンテンツ（ダッシュボード）はスクロール不可な状態になっている
- 「アプリを登録して始める」ボタンと「スキップして後で設定する」リンクが両方表示される

---

### TC-PLG-02: 既存ユーザーにはフローが表示されない

**優先度**: 🔴  
**前提**: `localStorage['onboarding_completed'] = 'true'` が存在するユーザー  
**手順**:
1. ログイン後、トップページを表示

**期待値**:
- オンボーディングオーバーレイが表示されない
- 通常のダッシュボードが表示される

---

### TC-PLG-03: 72h 超過ユーザーにはフローが表示されない

**優先度**: 🟡  
**前提**: `user.created_at` が 72h 以上前のユーザー、アプリ未登録、`onboarding_completed` なし  
**手順**:
1. ログイン後、トップページを表示

**期待値**:
- オンボーディングオーバーレイが表示されない
- 通常のダッシュボードが表示される

**エンジニアへの確認**: 72h 判定はフロントのみ（クライアント時刻）か、バックエンド（`/api/auth/me` のレスポンスにフラグを返す）か、どちらで実装するかを事前に確認すること。クライアント時刻の場合は端末時刻改ざんで回避可能なため、設計意図を PDM と合意すること。

## 2. AIキャプション生成

### 前提・設計確認ポイント（エンジニアと事前合意が必要）

- Claude API を使いキーワードからスクリーンショットキャプションを生成する
- 対象画面: `ScreenshotGenerator` のキャプション入力欄の隣に「AI生成」ボタンを追加
- 入力: アプリのキーワード一覧 + アプリ名 + 対象言語
- 出力: 各言語のキャプション文字列
- Proプランのみ利用可能（想定）

---

### TC-AI-01: 正常系 — キャプション生成成功

**優先度**: 🔴  
**前提**: Proユーザー、キーワード登録済み（3件以上推奨）  
**手順**:
1. ScreenshotGenerator を開く
2. 「AI生成」ボタンをクリック
3. API レスポンスを待つ

**期待値**:
- ローディング状態が表示される（ボタン無効化 + スピナーまたは「生成中...」テキスト）
- 各言語のキャプション欄にテキストが入力される
- 生成後すぐに編集可能な状態になる

---

### TC-AI-02: Claude API エラー時のフォールバック

**優先度**: 🔴  
**手順**:
1. Claude API が 5xx を返す状況（モック or ネットワーク切断）で「AI生成」をクリック

**期待値**:
- エラートースト or インラインメッセージが表示される（例:「キャプションの生成に失敗しました。もう一度お試しください」）
- ローディング状態が解除される
- 既存のキャプション入力内容は上書きされない（破壊しない）
- ボタンが再クリック可能な状態に戻る

**エンジニアへの確認**: API タイムアウト（例: 30秒）を必ず設定すること。タイムアウト時も同じエラーハンドリングに落とすこと。

---

### TC-BUG9-01: Stripe API エラー時のエラー表示

**優先度**: 🟡  
**前提**: Stripe API が失敗する状況（例: `STRIPE_SECRET_KEY` 未設定 → 503返却）  
**手順**:
1. UpgradeModal を開く
2. 「7日間無料トライアルを開始」をクリック

**期待値**:
- エラーメッセージがUI上に表示される（例: トースト「課金処理に失敗しました。時間をおいて再度お試しください。」）
- `isLoading` が `false` に戻る（ボタンが再クリック可能になる）
- コンソールエラーのみに留まらないこと

**修正後の確認コード（UpgradeModal.tsx の catch ブロック）**:
```typescript
// 修正前
} catch (err) {
  console.error('Failed to create checkout session:', err)
  setIsLoading(false)
}

// 修正後（期待形）
} catch (err) {
  console.error('Failed to create checkout session:', err)
  setError('課金処理に失敗しました。時間をおいて再度お試しください。')
  setIsLoading(false)
}
```

## 4. BUG-10 修正確認ポイント

### BUG-10: canvas context が null の場合に無言で空白PNGを生成

**現状の問題**: `drawFrame` 内で `canvas.getContext('2d')` が null を返した場合、`resolve()` してしまい、呼び出し元は空白のcanvasをPNGとしてダウンロードする。

---

### TC-BUG10-01: canvas context null 時のエラーハンドリング

**優先度**: 🟢  
**確認方法**: コードレビューで確認（自動テスト困難）

**修正後の期待コード**:
```typescript
// 修正前（NG）
const ctx = canvas.getContext('2d')
if (!ctx) return resolve()

// 修正後（期待形 — いずれか）
// A案: reject でエラーを伝播
const ctx = canvas.getContext('2d')
if (!ctx) return reject(new Error('Canvas 2D context is not available'))

// B案: 呼び出し元でエラートースト
// drawFrame が reject → downloadSingle/downloadAll の catch でトースト表示
```

**期待値**:
- context が取得できない場合、空白PNGがダウンロードされない
- ユーザーにエラーメッセージが表示される（「スクリーンショットの生成に失敗しました」など）

---

### TC-BUG10-02: 通常のダウンロード動作への影響がないこと（回帰）

**優先度**: 🔴（回帰テスト）  
**手順**:
1. 画像をアップロードし、キャプションを入力
2. 「↓ 日本語」ボタンをクリック（単言語DL）
3. ZIPダウンロード（Proユーザー）

**期待値**:
- 修正前と同じく PNG / ZIP が正常にダウンロードされる
- ファイルサイズが 0 バイトにならない（空白PNGでない）
- ダウンロードしたPNGを開いて、デバイスフレーム・背景・キャプションが表示されていること
