### ⚠️ キーワード制限の TOCTOU 競合（実装前に必須確認）

`service/keyword.go:46-57` の現在実装:

```go
count, err := s.repo.CountByApp(ctx, req.AppID)   // カウント取得
if count >= freePlanKeywordLimit { return ErrPlanLimitExceeded }
keyword, err := s.repo.Create(ctx, req)            // ← 別リクエストが割り込める
```

アプリ作成（BUG-8）と**同じ TOCTOU 競合**がキーワード制限にも存在する。

**キーワード用にも同様に実装すること**をエンジニアに事前確認・依頼すること。

### ✅ テンプレートルート認証（BUG-12 事前確認済み）

`main.go:285` の `r.Get("/templates", templateHandler.List)` は  
`r.Group` + `r.Use(authMiddleware.Verify)` の内側に配置されており、  
**JWT 認証は実装済み**。  
未認証アクセスは 401 を返す設計になっている。  
テストケースでは実際にトークンなしリクエストで 401 が返ることを確認する。

**優先度**: 🔴

---

### TC-KW-02: 11件目の登録で制限ブロック — 正常系

**優先度**: 🔴  
**前提**: Free ユーザー、キーワード 10 件登録済み  
**手順**:
1. 11件目のキーワードを追加しようとする

**期待値**:
- バックエンドが 402 Payment Required を返す
- フロントエンドで UpgradeModal が表示される（`triggerFeature="キーワード追加"`）
- キーワードは登録されない
- 既存の 10 件に変化がない

**確認コード（`apps/[id]/page.tsx:600` 付近の既存処理）**:
```typescript
if (err instanceof Error && err.message.includes('402')) {
  upgradeModal.open('キーワード追加')
}
```
このハンドリングが引き続き機能することを確認する。

### TC-KW-04: 並行リクエストでの制限回避 — セキュリティ

**優先度**: 🟡  
**前提**: Free ユーザー、キーワード 9 件登録済み  
**手順**:
1. 同一ユーザーで 11件目・12件目のキーワード追加リクエストをほぼ同時に送信  
   （開発者ツールや curl で並行 POST × 2）

**期待値（TOCTOU 修正済みの場合）**:
- 一方のみが成功（201）、もう一方が 402 になる

**期待値（TOCTOU 未修正の場合）**:
- 両方が 201 で 11 件以上登録されてしまう（リグレッション）

**エンジニアへの確認**: 実装前に `keywords` テーブルにユーザーレベルのロック機構が必要か確認すること。アプリ作成 `CreateWithLimit` と同様のパターンを採用することを推奨する。

## 3. BUG-12 テンプレート認証

### 背景

BUG-12 は Sprint 1 で「テンプレートの Pro ロックがフロントのみ」として軽微判定・バックログ化。  
Sprint 3 ではさらに「**未認証ユーザーへの API アクセス制御**」を確認する。  
現在の実装: `GET /api/templates` は `authMiddleware.Verify` グループ内に配置済み（`main.go:285`）。

---

### TC-T12-01: 未認証リクエストで 401 が返る

**優先度**: 🔴  
**手順**:
```bash

# Authorization ヘッダーなし
```

**期待値**:

- レスポンスボディに `{"error": "unauthorized"}` または同等

  https://<API_HOST>/api/templates
